## Conclusion

- **Same extension set** (all ten PreStocks extensions) on every leg, and **every behavioural field matches**: decimals, fee bps older and newer, maximum fee, null hook program, default state, pause flag, freeze authority present, confidential-transfer auto-approve.
- **Difference 1: TLV order.** A's mints store the same ten extensions in a different order. Token-2022 looks extensions up by type, and the basket program checks the extension *set*, so no scenario outcome depends on order. Only code that parses extensions at fixed byte offsets would notice. None of this project's code does.
- **Difference 2: OPENAI multiplier.** A's OPENAI fixture has an effective multiplier of 2 against mainnet's 1.4861347. That is the residue of A's multiplier-change-mid-position scenario, which changes it deliberately. It is display-only (spec 01).
- **Therefore A's issuer-scenario proofs stand on a fixture that is now verified, with its differences recorded.** Independently, the same issuer actions (pause, hook, frozen default state, multiplier) were run on Agent C's verified fixtures against the canonical basket (`ops@3b2deb9`); the spec owner verified all 12 signatures and the restored state at devnet slot 503685479.
